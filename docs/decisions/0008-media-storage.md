# 0008 — Media storage: signed URLs with a local/R2 switch

- **Date:** 2026-11-24
- **Status:** Accepted
- **Owner:** Product owner (local storage for dev now; R2 keys added later)

## Decision
- All uploads and downloads use **short-lived signed URLs**. Clients never hold storage credentials, and the API never streams large files in production.
- Storage sits behind one interface (`ObjectStorage`), selected by `STORAGE_BACKEND`:

| Backend | When | How |
|---|---|---|
| `local` (default) | Local development | Files on disk (`STORAGE_LOCAL_DIR`). The API emulates a bucket at `/api/v1/dev-storage/…`, with HMAC-signed PUT/GET links that include expiry, content type and maximum size. **Refused in staging/production.** |
| `r2` | Hosted environments (or local, to try R2) | Cloudflare R2 through its S3-compatible API. Upload URLs sign the exact `Content-Type` and `Content-Length`. The bucket must be **private**. Requires `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`. |

- Switching backends is configuration only. The API contract and the app don't change. Local URLs are API-relative (`/api/…`) and R2 URLs are absolute; the app resolves both.

### Upload flow (pet photos, and later documents and posts)
1. `POST /pets/{id}/photo/upload-url {content_type, size_bytes}` → `{media_id, upload: {url, method, headers}, expires_at}`.
   - Only JPEG, PNG and WebP are accepted, up to `MEDIA_MAX_IMAGE_BYTES` (default 8 MB).
   - At most 30 uploads per user per hour.
2. The app `PUT`s the bytes to `upload.url`, which is valid for 10 minutes.
3. `PUT /pets/{id}/photo {media_id}`: the API checks that the object exists, that its size matches what was declared, and that its **real type (from the file's first bytes)** matches. Then it attaches the photo.
   - A file that fails these checks is deleted.
   - Replaced or removed photos are deleted from storage.
4. Responses include `photo_url`, a signed download URL valid for 1 hour. Pet photos are **private** to the owner for now. Public delivery (community, provider profiles) will be decided per feature.

### Keys and records
- Object keys are generated by the server only: `pets/<owner_id>/<pet_id>/<media_id>.<ext>`. They are validated against a strict pattern, so path tricks fail.
- `media_assets` records each object: owner, purpose, key, type, declared and actual size, and status `pending` → `ready` → `deleted`.

## To set up R2 later
1. Cloudflare dashboard → R2 → create a bucket, e.g. `petfinity-dev`. Leave public access **off**.
2. R2 → *Manage API tokens* → create a token with **Object Read & Write** on that bucket only.
3. Set `STORAGE_BACKEND=r2` and the four `R2_*` values in `backend/.env` locally, or in the Render dashboard for hosted environments. Restart the API.
4. Add a CORS rule on the bucket only if a **web** client will upload. Native apps don't need one.
